# AGENTS.md – ASUS DialPad Driver

## Workflow / architecture

- **Name:** the project is shown as **Turnpad**; the technical name is `asus-turnpad`. All identifiers live in `config/identity.py` (Python) and `install_paths.sh` (shell); `tests/test_identity.py` keeps them and their JS/JSON/.desktop twins in sync. "DialPad" in docs names the ASUS hardware feature.
- **Modes** (names used in the UI and docs): **DialPad mode** (ASUS laptop with the printed DialPad: layouts, calibration, hidraw/I2C light), **Touchpad mode** (any other touchpad: config `emulation`, `dial_gesture.emulated_dial`), **Mouse-only mode** (no touchpad, a mouse: config `mouse`, `mouse_dial.py`, `listen_mouse_events`). In code and config the first is the default, the second is "emulation", the third "mouse mode".
- **Supported desktops:** GNOME (Shell extension) and the Wayland compositors with layer-shell: KDE Plasma 6, Hyprland, sway, niri, COSMIC (layer-shell dial `overlay/layer_shell.py`; sway tested in CI, KWin by hand with a GPU render node, the others untested). X11 sessions keep the legacy PySide window `dialpad_ui.py`. Other desktops start with an issue (`.github/ISSUE_TEMPLATE/desktop-support.yml`); do not add one unasked.
- **Before the rename** the project was installed as `asus-dialpad-driver` (`/usr/share/asus-dialpad-driver`, `~/.config/asus-dialpad`, D-Bus `io.github.asuslinuxdrivers.DialPad`, extension `dialpad@asus-linux-drivers`, services `asus_dialpad_driver@$USER`). `install_migrate.sh` moves settings and removes those leftovers on every install and uninstall.
- **Root:** Single-repo, single-app. No monorepo, no build steps; unit tests in `tests/`.
- **CI:** `.github/workflows/tests.yml` on GitHub Actions (every push and pull request) runs in an `archlinux:latest` container (Ubuntu's GTK/Libadwaita are too old): unit tests including the headless-mutter layout test, syntax checks, and `update_previews.py --check --only overlay`; job `arch-package` runs `packaging/arch/test-package.sh` (builds the Arch package from the commit, installs, checks files and imports, removes); jobs `deb-package` (ubuntu:latest, ubuntu:24.04, debian:trixie) and `rpm-package` (fedora:latest) do the same for `packaging/deb` and `packaging/rpm`; job `install` runs `tests/install_in_container.sh` (fedora:latest, ubuntu:latest, ubuntu:24.04; a GNOME and a sway install); job `layer-shell-dial` runs `tests/layer_shell_in_container.sh` on headless sway at scale 1 and 2 (artifact `layer-shell-dial`). Settings pictures are only rendered and attached to the run (artifact `rendered-pictures`): they show the apps installed on the desktop that renders them (Krita, Firefox, darktable icons), so they are updated locally.
- **Entrypoints:**
  - `dialpad.py` – main driver daemon, ~3000 lines, monolithic. Runs as the user service `asus-turnpad.service` with the system `/usr/bin/python3`.
  - `dialpad_ui.py` – legacy PySide6 overlay for X11 sessions, separate `asus-turnpad-ui.service` (template `asus-turnpad-ui.x11.service` only). On GNOME replaced by `gnome/extension/`, on other Wayland desktops by `overlay/layer_shell.py`.
  - `install.sh` – bash installer for every distribution (unattended; `--interactive` asks), sources sub-scripts from repo root. Refuses to run while the Arch package is installed. Installs distribution packages only (`install_packages.sh`: groups per package manager, optional ones one by one); no venv, no pip, no compiler or `-dev` headers (`tests/test_install.py` maps every imported library and GI namespace to its package).
  - `packaging/` – distribution packages: `arch/PKGBUILD` (`asus-turnpad-git`, builds the latest GitHub commit; deps from the Arch repos, no venv), static user units `asus-turnpad.service` (layout `auto`) and `asus-turnpad-overlay.service` (layer-shell dial), udev rules (uaccess + groups), modules-load, sysusers, and `asus-turnpad-setup` (per-user: groups, enable the driver service, then the extension on GNOME or the dial's service on other Wayland sessions when `Gtk4LayerShell` imports; runs under `set -u`, so `${XDG_CURRENT_DESKTOP:-}`; refuses while an `install.sh` install exists). `gtk4-layer-shell` is optional: PKGBUILD optdepends, deb/rpm Recommends. `arch/build.sh` runs `makepkg -si` in `~/.cache/asus-turnpad/makepkg` (makepkg rewrites `pkgver` in the PKGBUILD it uses, which would dirty the clone); `arch/test-package.sh` tests it in a clean container. `install-files.sh <root> [--no-bytecode]` is the one file list of all packages (PKGBUILD, `deb/debian/rules`, `rpm/asus-turnpad.spec` call it; every root `*.py` but `dialpad_ui.py`, explicit extension files). `deb/` (debhelper, `dh_python3` compiles at installation, the user unit is not enabled globally) and `rpm/` (spec, `%py_byte_compile`) each have `build.sh` (`git archive` of HEAD, a commit or `--worktree` into a temp dir; version `0.r<commits>.<hash>`; output in `~/.cache/asus-turnpad/{deb,rpm}`) and `test-package.sh` (apt/dnf install without recommends, files, `check-imports.py`, `asus-turnpad-setup` as a user, remove). Their dependency lists match `install.sh`; Fedora also needs `gobject-introspection` (cairo typelib). `tests/install_in_container.sh` runs `install.sh` + `uninstall.sh` in Fedora/Ubuntu containers (CI job `install`); `INSTALL_IN_CONTAINER=1` (install_common.sh) skips the touchpad check, modprobe and starting services. The settings app needs Libadwaita 1.5 and GTK 4.14 (Ubuntu 24.04, Debian 13); newer widgets get a fallback (`_page_sidebar()` for `Adw.ViewSwitcherSidebar`, `_button_row()` for `Adw.ButtonRow`), and `install.sh` warns below 1.5. Users read `INSTALL.md`.
- **Install target:** `install.sh` → `/opt/asus-turnpad/`, owned by root, system Python (`PYTHON` in `install_paths.sh`) (FHS layout in `install_paths.sh`); Arch package → `/usr/share/asus-turnpad` (`identity.PACKAGE_DIR`), system Python. Code must not assume either path (it finds files next to itself). User data: `~/.config/asus-turnpad/` (`config.json`, `skins/`, driver state `dialpad_dev`). Source and installed versions can diverge; diff before debugging.
- **Fork additions:**
  - `layout_detect.py` – layout for this laptop from `laptop_touchpad_dialpad_layouts.csv` (product name, then touchpad vendor/product id; fallback `proartp16`). `dialpad.py auto` uses it; `install_layout_auto_suggestion.sh` runs it as a script. Nix packaging was removed (stale, old names).
  - `dialpad_dbus.py` – session D-Bus service (`io.github.sinu0.AsusTurnpad.Driver`), signal `OverlayState(bsasasidsbbb)`.
  - `dial_gesture.py` – pure gesture maths (angle, slices, `RotationTracker`), no hardware imports; unit tested.
  - **Security:** services keep `NoNewPrivileges=yes` (dial commands must never reach root, the user may have passwordless sudo); the driver needs no privileges (I2C via group, hidraw via uaccess). `config.schema.shell_commands()` lists commands of imported profiles and the app asks before importing them. Skins must stay data only.
  - `launch.py` – runs Command/Shell steps: in their own `systemd-run --user --scope` (they survive driver restarts), waiting at most 2 s so a program with a window never blocks the action thread. Functions with no turning actions are launchers: `select_multifunction_segment()` runs their tap action straight from the menu (library category "Launch").
  - `backlight.py` – DialPad light brightness: `commands_for_level()` (0 = light off while the dial works, 1–8 = values `0x41`–`0x48` after `0x01`) and `KeyboardBacklight` (UPower `KbdBacklight` on the system bus, keyboard off = light off; change signals arrive in the D-Bus service's GLib loop). Config section `backlight` (`follow_keyboard`, `level`); the driver applies it through `apply_backlight()` on the action thread, never on the touch thread.
  - `tests/` – `unittest` suite for gesture maths, legacy adapter and D-Bus overlay state.
  - `config/` – JSON config model, macro runtime, legacy adapter, migration from old `dialpad_dev` INI + `layouts/*.py`.
  - `config/presets.py` – ASUS Dial-style function library (categories in `LIBRARY_CATEGORIES`, ready groups in "Groups": Apps, Clipboard, Media controls, System, Navigation, Documents) and pre-programmed app packs. Every `AppPack` has a basic variant (`factory`, ≤ 6 functions, no groups) and an advanced one (`advanced`, ≤ 8 sectors with groups by the stages of the work, `advanced_look` = the profile's dial look, e.g. the menu at the top for timeline editors); `profile_for_app(name, app_id, advanced)`, `profile_for_pack(pack, advanced)`, `variant_summary()`; the settings app asks which (`_choose_pack_variant()`). Function looks `CANVAS` (pill), `VIEW` (fade) and `TIMELINE` (top, fade) keep the dial off the work. Shortcuts are the applications' defaults, checked against their sources (comment per pack); keys go to the window under the pointer. `tests/test_presets.py` checks sizes, unique titles, evdev key names, valid looks, round trips and which pack matches which desktop ID. `suggested_color()` colours functions without one.
  - `config/profile_share.py` – profiles as text: `PROFILE_FORMAT` + `ai_prompt()` for assistants, `profiles_from_text()` reads an answer, a profile or an export file (normalises key names via `labels.parse_keys`, raises `ProfileTextError` with a readable reason); used by Dial Controls › Build with AI and by file import. Keep `PROFILE_FORMAT` in sync with the schema.
  - `config/labels.py` – key/macro labels shared by the GUI and the overlay hints (includes the evdev code table for old numeric keys); `parse_keys()`/`keys_to_text()` read and write typed shortcuts ("Ctrl+F12"); `ICON_RULES` must match `dial.js` (`tests/test_labels.py`), `ICON_CHOICES` feeds the icon picker.
  - `config_app/` – GTK4/Libadwaita settings GUI (`io.github.sinu0.AsusTurnpad`).
  - `gnome/extension/` – GNOME Shell 45–51 extension (`asus-turnpad@sinu0.github.io`), renders radial dial natively. `dial.js` holds all painting and imports only `cairo` (shared with `tools/`); `extension.js` owns actors, D-Bus and config watching; `layers.js` paints in three layers (background, content, finger dot) that repaint only when their look changes, see "Rendering cost" in `ARCHITECTURE.md`. A group's list is a separate actor (child of the dial) painted by `paintSubmenu()`, placed by `submenuPlacement()` beside the dial on the dial's monitor (side of the group's sector, smaller rather than over the dial on a small screen, also next to a dial at position `pointer`; `tests/test_overlay_placement.py`) and slid in with an ease. Every extension file must be listed in `install.sh` and `install_gnome_extension.sh` (`tests/test_install.py`).
  - `gnome/extension/skins.json` – built-in skins (`glass`, `midnight`, `frost`, `proart`, `classic`); user skins are `~/.config/asus-turnpad/skins/<id>.json`. Format and AI workflow in `SKINS.md`.
  - `config/skins.py` – loads/resolves skins in Python (mirrors `resolveSkin()` in `dial.js`, keep both in sync); `PALETTE_KEYS` drives the editor, `SKINS.md` and the AI prompt. Skins also carry `shape` (`DIAL_SHAPES`), `outline` (custom polar outline, points clamped by `outline_limit()` to the dial square), `tile`, `tileSize` and `background` (PNG next to the skin file; loaders add the private `__dir` key, `without_private_keys()` strips it before saving). Shape paths exist twice: `shapePath`/`tilePath` in `dial.js` and `shape_path`/`_tile_path` in `overlay/painter.py`; `tests/test_skins.py` checks the shared lists and limits.
  - `config_app/outline_editor.py` – the drag-the-points outline editor (polar grid, snapping, mirror, presets).
  - `overlay/painter.py` – toolkit-free Cairo port of `dial.js` (settings app previews now, overlays on other desktops later); icons come through a callback, `overlay/gtk_icons.py` for GTK. Keep geometry in sync with `dial.js` (also `paint_submenu()` with `paintSubmenu()` and the `LIST_*` constants).
  - `overlay/layer_shell.py` + `overlay/frontend.py` – on-screen dial for layer-shell compositors (KDE Plasma 6, Hyprland, sway, niri, COSMIC). GTK 4 + `Gtk4LayerShell`: overlay layer, no keyboard, empty input region, the compositor picks the output (`--output NAME` pins it). Run with the system `python3`; it restarts itself once with gtk4-layer-shell in `LD_PRELOAD`. Exit 3 = no layer-shell (GNOME, X11); services don't restart then. `overlay/look.py` and `overlay/visibility.py` are Python twins of `dial.js`/`extension.js` (placement, look, pill, icons, finger dot, state, fade timing, group lists: `open_submenu`, `submenu_size`, `submenu_placement`, `submenu_layout`, `submenu_key`, `LIST_*`); `painter.paint_background/paint_content/paint_pointer` twin the dial.js layers and `painter.paint_live_submenu` twins `paintSubmenu()` plus the list's icon actors — change both sides together. A group's list is a third layer window (`GroupList` in `overlay/frontend.py`) pinned to the dial's output, its opacity the dial's times its own (it shows, fades and hides with the dial) and its picture sliding inside a window that reaches `LIST_SLIDE` towards the dial; `tests/test_overlay_look.py` (gjs) and `tests/test_live_painter.py` (pixels; group lists must be pixel-identical) fail when they drift; `tests/dial_cases.py` holds the shared states (three with groups: an open list on each side, a function chosen from a group); `tests/layer_shell_in_container.sh /src sway OUT [scale]` runs it on headless sway (CI job `layer-shell-dial`), `kwin` instead of `sway` on headless KWin (by hand: `podman run --device /dev/dri/renderD128`, KWin 6.8 has no renderer without a DRM render node; output scale via `kwinoutputconfig.json`, not `--scale`). Installed as the user service `asus-turnpad-overlay.service` (`install_layer_shell_overlay.sh`, `packaging/asus-turnpad-overlay.service`); the session must hand `WAYLAND_DISPLAY` to the user manager and start `graphical-session.target`.

  - **Mouse-only mode** ("mouse dial"; config section `mouse`: `enabled`, `device` = part of the input device's name, `""` = first device with the toggle key and a wheel, `toggle_key` = evdev key or `BTN_` name, normalised by `config.schema.normalize_key_name()`, `motion` (default off) and `motion_radius` (mouse counts, 50–2000, default 300); settings app *Driver* page, group "Mouse"; restarts the driver) for computers without a touchpad. `mouse_mode` is read once at start and wins over `emulation` (which is then off): no touchpad is detected or opened (`d_t`/`fd_t` are `None`, `max_x`… are 0), no hidraw/I2C (`send_value_to_touchpad()` sends nothing), no calibration (`on_dbus_start_calibration` → false), `GetStatus()["mouse"]`. `mouse_dial.py` is pure (no hardware imports, `tests/test_mouse_dial.py`): `find_mouse()` parses `/proc/bus/input/devices` (name substring, key bit in `B: KEY=`, REL_WHEEL bit in `B: REL=`, names containing "DialPad" = the driver's own virtual device are skipped), `MouseDial` turns toggle key / `REL_WHEEL` notches (down = clockwise, `REL_WHEEL_HI_RES` ignored) / `BTN_MIDDLE` / `BTN_LEFT` / `BTN_RIGHT` + `tick(now)` into `toggle`, `rotate`, `center_press`, `center_hold` (once, middle button only), `center_release(duration, hold_fired)` (the left button is the centre too, one centre button at a time, its release always has duration 0 = a tap, so no hold-to-go-back) and `back` (right button press); `MousePointer` is the optional motion, a heading model: the dial angle is the direction the hand moves (`dial_gesture.touch_angle` of the displacement from the trail point `motion_radius / 2` counts of travel back to now: up = 0, right = 90, clockwise circling turns it clockwise, one dial turn per lap whatever the size of the circle). After `reset()` there is no angle (`in_dead_zone`) until the hand has travelled 35 % of `motion_radius`, then always one (a wiggle with a net displacement under 25 % of the window's travel keeps the previous angle); `jumped` says the last `move()` turned the angle by more than 100° (the hand reversed), and the driver then starts the `RotationTracker` again instead of counting a turn (in the menu a jump just picks the new sector). `listen_mouse_events()` runs on the main thread instead of `listen_touchpad_events()` (`select` with 50 ms timeout, mouse searched every 2 s, closed on `OSError`); it maps the actions onto the state functions the touch loop uses: `rotate_dial()` (`rotate_menu_highlight()` wraps over the filled sectors, `move_submenu_highlight()` in a list, `rotate_selected_function()` → `queue_rotation_action()` in a function), `release_center()` (the touch loop's lift decision, shared), `show_menu_after_gesture()`, `leave_function()` for the hold and the right button. With `motion` the loop feeds the pass's summed `REL_X`/`REL_Y` to the pointer and does what the touch loop does with a finger's angle: `highlight_menu_slice()` (sector the hand points to, only on change), a `RotationTracker` with `SUBMENU_STEP_DEGREES / sensitivity` → `move_submenu_highlight()` in a list, `turn_selected_function()` (threshold, scroll threshold, sensitivity, scroll multiplier → `queue_rotation_action()`) in a function; both helpers are shared with the touch loop, the finger dot follows the touch loop's `POINTER_STEP` rule outside the dead zone (`pointer=-1` inside it). The pointer is reset (no angle until the hand has travelled again) when the dial turns on and after entering or leaving a function or list. The wheel works in both settings; keep these in `STATE_FUNCTIONS` of `tests/test_driver_state.py`. The loop follows `dialpad` (so D-Bus `Toggle` and the inactivity timer work): it sends `{"touching": ...}` while the dial is on and grabs/ungrabs the device (`set_mouse_grab()`, under `mouse_lock`; `close_mouse()` in `cleanup()`), but never while the toggle key is held, so the desktop sees both press and release of the key that opens the dial (the opening press itself still reaches the desktop: a key the desktop does not know, e.g. F13 mapped with Piper, avoids a side effect). `process_pending_driver_updates()` runs every pass, with `gesture_idle=False` while the middle button is down. The keyboard (modifier tracking) is still looked up by name, so `with_modifier` variants need a keyboard the detection knows.
  - **Touchpad mode** ("DialPad emulation"; config section `emulation`: `enabled`, `corner`, `center_size`; settings app *Driver* page) for touchpads without a DialPad: read once at driver start (the app runs `systemctl --user reset-failed` + `restart`), any touchpad (`layout_detect.is_touchpad()`), no hidraw/I2C and `send_value_to_touchpad()` sends nothing. Geometry from `dial_gesture.emulated_dial()` (ring = whole touchpad, centre = `center_size` % of the shorter side, 15 mm corner, `x_scale` for unequal axis resolutions). While on, `set_emulated_dial_owns_touchpad()` grabs the evdev device and disables send-events (on the action thread), so libinput resyncs when it gets it back; every touch is the dial except one that starts on the corner. The driver starts with it off, re-enables send-events at start and on SIGTERM (emulation only), refuses calibration. Tests: `tests/test_emulation.py`.

## Developer commands

- **Unit tests:** `python3 -m unittest discover -s tests -v`
- **Syntax check driver:** `python3 -c "import ast; ast.parse(open('dialpad.py').read())"`
- **Check all Python:** `python3 -m compileall -q config config_app desktop overlay tools dialpad_dbus.py`
- **Verify bash scripts:** `bash -n install*.sh uninstall.sh`
- **Smoke test config:** `python3 -m config.runtime && python3 -m config.legacy_adapter`
- **Validate GNOME extension (outside Shell):** `gjs -m gnome/extension/extension.js` – will fail with resource import errors because `resource:///org/gnome/shell/ui/main.js` only exists inside the shell process; that is expected and confirms ESM syntax is valid.
- **Desktop file validate:** `desktop-file-validate config_app/io.github.sinu0.AsusTurnpad.desktop`
- **README pictures:** `python3 tools/update_previews.py` renders everything in `preview/` and replaces only pictures that really changed (rendering noise stays below a tolerance, so unchanged pictures are not re-committed); `--check` only reports. Run it before every push that touches the extension, settings app, painters or skins and commit the changed pictures. The settings app renders in a headless mutter (own D-Bus session, virtual 2560×1600 monitor), so no window appears and focus cannot spoil the pictures; `--visible` opens it on the desktop instead. `tools/git-hooks/pre-push` enforces it once enabled with `git config core.hooksPath tools/git-hooks` (skip once: `SKIP_PREVIEWS=1 git push`). Pictures never read the desktop's settings (`GSETTINGS_BACKEND=memory`, `ScreenshotApp` pretends a dark desktop); `--only overlay` compares only those pictures, `--output DIR` keeps everything rendered.
- **Overlay on monitors 1080p–4K:** `tests/test_overlay_placement.py` runs `overlayPlacement()` from `dial.js` in gjs for common monitors and GNOME scale factors (logical pixels; the PX13 at 200 % is 1440×900); the dial must stay on screen and top ≤ center ≤ lower ≤ bottom; position `pointer` keeps it beside the pointer; a group's list (`submenuPlacement()`) stays on screen beside a dial at every position.
- **Settings app layout 1080p–4K:** `tests/test_settings_layout.py` runs `tests/layout_probe.py` in one headless mutter per window size, in parallel (~9 s); it visits every page and the main dialogs and fails on widgets past the window edge, a window that cannot shrink to the size, or GTK warnings. Add new pages to `PAGES` and new dialogs to `dialogs()` there. On the oldest supported Libadwaita (1.5): `podman run --rm -v "$PWD:/src:ro" ubuntu:24.04 bash /src/tests/settings_in_container.sh /src`.
- **Test D-Bus service standalone:** `python3 dialpad_dbus.py` – starts, emits one invisible state, exits.

## Key environment facts

- **System:** CachyOS (Arch-based), GNOME Shell 51 (extension metadata lists 50 and 51), Wayland, Python 3.14, GTK 4.24, Libadwaita 1.10.
- **Laptop:** ASUS ProArt PX13 HN7306WV. Touchpad `ASCF1A00:00 2808:0220` (min-max x 0-4010, y 0-2443).
- **Layout:** `proartp16` used as fallback. Geometry in legacy layout may not match PX13 — needs calibration.
- **Python libraries:** distribution packages for the system Python (Arch package: PKGBUILD depends; `install.sh`: `install_packages.sh`). No venv; `install_migrate.sh` removes an old `/opt/asus-turnpad/.env` and services that ran it.

## GNOME Shell extension lifecycle

- GNOME Shell **does not reload extension code** on disable/enable; a full Shell restart (logout/login) is required after code changes.
- `gnome-extensions enable` will report ERROR until Shell has loaded the extension once.
- Use `gdbus call --session --dest org.gnome.Shell --object-path /org/gnome/Shell --method org.gnome.Shell.Extensions.GetExtensionErrors 'asus-turnpad@sinu0.github.io'` to read errors.
- `import * as Main` (named), not `import Main from` (default) for `resource:///org/gnome/shell/ui/main.js`.
- Extension replaces `asus-turnpad-ui.service` on GNOME; the config app calls `ReloadConfig` via D-Bus after saving.

## D-Bus contract

| Item | Value |
|---|---|
| Bus name / Interface | `io.github.sinu0.AsusTurnpad.Driver` |

## Config migration behavior

- First launch of the Turnpad app migrates old `dialpad_dev` INI + `layouts/proartp16.py` into `~/.config/asus-turnpad/config.json`.
- If JSON exists, migration is skipped. To re-migrate: delete the JSON file first.
- The driver loads JSON config at startup if it exists; otherwise falls back to legacy layout Python.
- Macros (`MacroStep` list) appear as `{"macro": [...]}` inside legacy `app_shortcuts` dict entries. `emulate_shortcuts()` handles them before legacy key/command logic.

## Profiles and dial behaviour (ASUS Dial parity)

- Profile fields: `mode` (`multi` radial menu / `single` bound function + `single_function`), `sensitivity` (divides rotation thresholds), `scroll_speed` (multiplies scroll units), `remember_last`.
- Segment fields: `enabled`, `color`, `with_modifier` (`{"Ctrl"|"Shift"|"Alt": ModifierActions}`, own `macro_cw/ccw/center` while that key is held; `MODIFIER_KEYS` in `config/schema.py`), `items` (a list makes the segment a group; `None` = a function). Groups go one level deep (the decoder drops `items` of items), have no actions of their own, and a group without enabled items is left off the dial; `single_segment()` never binds a group. The legacy adapter writes a group as `{"items": {title: legacy segment}, "icon": GROUP_ICON, …}`; `config.schema.all_functions()` walks functions inside groups too (`shell_commands()` names them `Group › Function`). The adapter adds them as entries with `"modifier": [left, right key names]` after the plain entry; `shortcuts_for_modifiers()` in the driver runs the entries of a held key, otherwise the plain ones (a function without a variant keeps working while a key is held). The keyboard listener only follows keys in `modifiers`, which `enable_config_macro_capabilities()` fills from these entries. Use `Segment.macro_lists()` for anything that must see every step (`shell_commands()`, import checks). MacroStep scroll fields: `axis` (`horizontal`), `modifiers` (keys held while scrolling, e.g. Ctrl = zoom). Never reuse a scroll step's legacy `keys` (old configs contain junk like `["8","11"]`).
- The legacy adapter puts profile settings under the reserved `_meta` key; `is_multifunction()` skips keys starting with `_`. Single mode uses the flat `clockwise/counterclockwise/center` layout with `_meta.single` holding title/treshold/value/unit/color/hints.
- In a selected function: tap centre = the function's `macro_center` if any, otherwise back to menu; holding the centre for `gesture.center_hold_time` returns to the menu (fires while still touching).
- Groups: choosing a group's sector opens its list (`open_submenu()`; driver globals `submenu` = group title, `submenu_index`); turning moves the highlight one item per `SUBMENU_STEP_DEGREES / sensitivity` and stops at the ends, lifting the finger keeps the list, a centre tap runs `select_multifunction_segment()` on the highlighted item (a launcher runs and the list stays), holding the centre runs `leave_function()`: one level back, from a function of the group to its list, from the list to the menu. `function_entry()` looks a title up in the open group's items, else in the menu; use it instead of `app_specific_shortcuts[title]`.
- Dial look per level: `overlay` defaults (`position` incl. `custom` + `custom_x`/`custom_y` = dial centre as screen fractions and `pointer` + `pointer_side` (`POINTER_SIDES`, default `below-right`) / `pointer_gap` (logical px 0–400, default 24, not multiplied by `scale`), `visibility` `full`/`fade`/`pill`, `fade_opacity` %) ← `Profile.overlay` ← `Segment.overlay` (dicts of overrides, validated by `overlay_rule()`). The driver merges profile + function (`overlay_look()`, also in single mode via `_meta.single.overlay`) into `details.look`; the menu uses the profile's. The extension resolves the rest with `effectiveLook()` in `dial.js`; `fade` = full on touch, fades after `FADE_AFTER_MS`; `pill` = a small St label (`pillContent()`/`pillPlacement()`) instead of the dial. Settings app: `_dial_look_rows()` (plain on the Skins page, folded "On-screen dial" row in profile and function editors, screen picker for custom, side and distance rows for "Near the pointer").
- Position `pointer`: `besidePointer()` in `dial.js` (twin `beside_pointer()` in `overlay/look.py`) puts the dial's box (dial + hints; the pill likewise) on the chosen side of the pointer, `pointer_gap` away, straight sides centred on it. A side without room flips to the opposite one, a straight side then tries the two across it; the box is then clamped on screen and covers the pointer only when no side leaves room. The pointer is read only when a fully hidden dial shows (`_followPointer()`; fading counts as shown), so the dial never moves while visible, also not on a look change; without a known pointer it is `lower`.
- `last_function_by_app` holds `(group, function)` (group `None` in the menu) and restores the last function on activation and focus change; returning to the menu or to a group's list forgets it. A focus change to another app never keeps the previous app's function.
- `overlay` section of config.json (scale, position, hide_delay_ms, show_hints, show_pointer, accent, skin, skin_light, follow_system_style) is read directly by the Shell extension through a directory monitor (also on the skins directory); the driver does not use it except `show_pointer`. With `follow_system_style` the extension uses `skin_light` unless `org.gnome.desktop.interface color-scheme` is `prefer-dark`.
- `tests/test_driver_state.py` extracts the state functions from `dialpad.py` via AST; keep their names in `STATE_FUNCTIONS` in sync when renaming.

## Guided calibration and other models

- `dial_gesture.CalibrationSession` (pure, tested) fits the outer ring and the centre button from finger traces (`fit_circle`, `angular_coverage`). The driver routes whole touch frames to it while `calibration` is set and skips activation and dial actions; send-events are disabled meanwhile.
- The settings app applies the result live and asks *Keep* / *Revert* (`_calibration_backup` holds the geometry before; closing the app without choosing reverts in `do_shutdown`). It stores `device_name` = layout; `apply_gui_settings()` ignores JSON geometry whose `device_name` differs from the running layout.
- *Reset geometry* restores the running layout's values via `config.migrate.layout_geometry()`, which parses the layout file with `ast` (layouts import `libevdev`); the toast offers Undo.
- First-run migration detects the layout via `GetStatus()` or the `dialpad.py` process arguments — never hard-code `proartp16`.
- `details` payloads never go to the Unix socket (the PySide overlay `dialpad_ui.py` reads newline-delimited JSON and applies only the keys present).
- See `PORTING.md` for the user-facing steps.

## Touch input pipeline

- Frame-based processing in `listen_touchpad_events()`: events buffered per slot, gesture logic runs once per `SYN_REPORT`.
- Global state mutation is serialised through `driver_state_lock` and `process_pending_driver_updates()` called at start of each frame.
- Per-frame recalculations of `circle_radius` and bounds allow live calibration changes.
- Constants: `DEBOUNCE_MS=30`, `SETTLE_FRAMES=3`; hysteresis comes from `gesture.hysteresis` in JSON (default 3 without JSON).
- `RotationTracker.reset()` must run on touch down, lift, centre and leaving the ring, or the next touch jumps.
- `finger_down` follows the one finger the dial tracks (`dial_touch_id`, chosen by `dial_gesture.select_dial_touch`): the touch already followed, else the newest touch inside the ring or on the corner icon. Other fingers, a resting palm and touches reported as `MT_TOOL_PALM` are ignored, and lifting the tracked finger counts as release even while others stay down. Never clear `slots` on release; `update_touch_slots()` keeps them in sync (also from `d_t.sync()` after `SYN_DROPPED`).
- Actions, shell macros and value queries run on the `dialpad-actions` worker thread via `enqueue_action()`; never call subprocesses from the touch loop.
- Configuration reloads and application changes wait while the dial tracks a finger (applied at the end of the lift frame); calibration requests do not.
- Every send to the virtual device holds `uinput_lock`; `reset_udev_device()` (on the action thread after a reload, on the keymap threads otherwise) swaps the device under it, releases held scroll modifiers on the old device and destroys it with `close_virtual_device()` (python-libevdev's reference cycles would keep it alive).
- The GNOME overlay shows while `touching`, and fades out 1.5 s after release. It appears on the monitor with the pointer (`_followPointer()` in `extension.js`) and stays there while visible, even if the pointer moves to another monitor; only a fully hidden dial follows the pointer again. The layer-shell dial gets the same effect from the compositor: its window is unmapped only when fully hidden, so the compositor picks the output again on the next show. With position `pointer` it asks `desktop/pointer.py` at that moment (Hyprland only, a local socket with a 50 ms timeout) and pins both windows to the pointer's output; elsewhere it shows at `lower`.

## Formatting

- `dialpad.py` uses CRLF line endings (DOS format). Adding code with LF endings triggers `git diff --check` whitespace warnings. Use `unix2dos dialpad.py` after editing if needed.
- Other files use standard LF.
